## 사례 1. 상호작용 키를 눌러도 상자가 열리지 않는 문제

- **상황:** 상자 근처에서 상호작용 입력을 해도 대화 이벤트가 먼저 실행되어 상자 열기가 처리되지 않았습니다.
- **원인:** 대화 처리와 상자 처리의 입력 우선순위가 충돌했습니다.
- **수정:** 상자 대상이 있을 때 `E` 입력을 먼저 처리하고 반환하도록 분기를 추가했습니다.
- **근거:** `d2998ba`의 커밋 설명과 수정 코드. [공개 발췌](../Scripts/BugFixes/ChestInputPriority.Excerpt.cs)
- **확인할 항목:** 상자 근처의 E 입력, 일반 대화, 선택지 입력을 각각 재현합니다. 현재 버전에는 이 분기 앞에 이벤트 진행 가드가 있으므로 모든 이벤트 중 상자 열기를 허용하는 구조는 아닙니다.

## 사례 2. 엔딩 씬 진입 후 UI 충돌과 대화 정지

- **상황:** 이전 씬에서 유지된 Canvas·매니저가 엔딩 씬의 UI와 충돌하거나, 플레이어가 없는 엔딩에서 기존 입력 경로를 사용할 수 없었습니다.
- **수정:** 엔딩의 UI와 TalkManager를 GameManager에 다시 연결하고, 엔딩 전용 대화 입력을 추가했습니다. 타일맵이 없는 씬에서 이동 코드가 실행되지 않도록 방어 조건을 추가했습니다.
- **연출:** 페이드가 끝난 뒤 대화 시작 오브젝트를 활성화하도록 순서를 정리했습니다.
- **근거:** `a382ba5`의 커밋 설명 및 [EndingSceneSetup](../Scripts/Ending/EndingSceneSetup.cs), [EndingInput](../Scripts/Ending/EndingInput.cs), [타일맵 방어 코드](../Scripts/BugFixes/PlayerMovement.NullGuards.Excerpt.cs).
- **확인할 항목:** Act 5에서 엔딩 진입, UI 중복 여부, 엔딩 대화 넘김, 페이드 종료 후 대화 시작 순서.

## 사례 3. 초상화가 없을 때 흰 사각형이 표시되는 문제

- **상황:** 초상화가 없는 대화에서 UI Image가 흰 영역으로 남았습니다.
- **수정:** 유효한 Sprite가 있을 때만 표시하고, 없으면 알파를 0으로 설정하고 Sprite 참조를 비웠습니다.
- **근거:** `a382ba5` 및 [PortraitFallback.Excerpt.cs](../Scripts/BugFixes/PortraitFallback.Excerpt.cs).
- **확인할 항목:** 초상화가 있는 대화에서 없는 대화로 전환했을 때 잔상이 남지 않는지 확인합니다.

## 사례 4. 비운 상자에 아이템이 다시 생성되는 문제 (2026.10.13 발견, 미수정)

포트폴리오 정리 중 `ChestController.cs`를 다시 읽다가 발견했습니다. 상자를 모두 비우면 슬롯 저장 키가 삭제되고, 다음 로드 때 이를 '처음 여는 상자'로 판단해 아이템을 재생성합니다. 원인과 최소 수정안은 [README](../README.md#포트폴리오-정리-중-발견한-버그)에 정리했습니다. 공개 코드는 원본 해시를 유지하기 위해 수정하지 않았습니다.

## 엔딩 조건 재현 도구

[EndingTester.cs](../Scripts/BugFixes/EndingTester.cs)는 Unity Editor에서 사용하는 수동 테스트 보조 코드입니다.

| 입력 | 조건 설정 |
| --- | --- |
| F1 | `flag.normalsua` 제거 |
| F2 | `flag.normalsua` 설정, 일기 플래그 4개 제거 |
| F3 | `flag.normalsua`와 일기 플래그 4개 설정 |
| F5 | 지정한 대화 ID로 대화 시작 |

최종 분기 결과는 원본 대사 CSV와 게임 상태에 따라 결정됩니다. 이 표는 테스트 도구의 입력 동작을 설명하며 모든 엔딩의 자동 검증을 뜻하지 않습니다.
